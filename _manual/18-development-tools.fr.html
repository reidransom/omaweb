Éditeurs alternatifs #

Omarchy est livré avec Neovim par défaut, mais si vous préférez quelque chose d’un peu plus grand public et familier, vous pouvez ouvrir le menu Omarchy (Super + Space) et consulter les options sous Installer > Éditeur. Vous y trouverez VSCode, Cursor, Zed, Sublime Text, Helix, Vim et Emacs. Si vous ne trouvez pas ce que vous cherchez, consultez Installer > Paquet pour voir s’il existe dans un paquet Arch (sinon, essayez Installer > AUR pour rechercher dans l’AUR).

L’harmonisation du thème est proposée pour VSCode, Cursor, VSCodium et Helix.

Vous pouvez définir l’éditeur par défaut pour l’ensemble du système sous Setup > Defaults > Editor.

Environnement #

Omarchy permet de configurer toute une série d’environnements de développement depuis la section Installer > Développement du menu Omarchy (Super + Space). Vous y trouverez bien sûr Ruby on Rails, mais aussi les trois principaux environnements d’exécution JavaScript (Node.js, Bun et Deno), ainsi que des frameworks PHP populaires comme Laravel et Symfony. Il y a également Go, Rust, Python, Java, Elixir (avec Phoenix), .NET, OCaml, Zig, Clojure et Scala. Le choix est très vaste !

La plupart de ces environnements sont gérés par Mise. Cet outil vous permet d’installer et d’exécuter plusieurs versions d’un langage de programmation sur une même machine. C’est l’équivalent de rbenv ou rvm pour Ruby, ou de virtualenv pour Python, mais il fonctionne avec de nombreux environnements différents.

Pour installer Ruby, par exemple, exécutez mise use -g ruby : cette commande installera Ruby et le définira comme version globale par défaut. Si votre projet contient un fichier .ruby-version, vous pouvez simplement exécuter mise i à la racine de ce projet.

Docker #

Docker n’a guère besoin d’être présenté. Il vous permet d’exécuter des conteneurs isolés, et Omarchy installe tout le nécessaire pour l’utiliser dans de bonnes conditions, notamment Docker lui-même et Docker Compose.

Par défaut, votre utilisateur ne fait pas partie du groupe docker. Ce groupe équivaut en pratique à un accès root sans mot de passe : tout processus qui en fait partie peut exécuter docker run -v /:/host et prendre le contrôle de la machine. Sans cette précaution, il suffirait donc d’une seule commande à un script ou à une dépendance malveillante s’exécutant avec vos droits pour obtenir un accès root. En ligne de commande, vous devez donc exécuter Docker avec sudo (sudo docker ps, sudo docker compose up), tandis que les outils graphiques qui communiquent avec le démon — la TUI Docker accessible avec Super + Shift + D et la machine virtuelle Windows — demandent une autorisation lorsqu’ils en ont besoin. Si vous souhaitez retrouver la commodité d’une configuration sans sudo et que vous en comprenez les risques, activez-la depuis Configuration > Sécurité > Docker sans sudo (ou exécutez omarchy-setup-security-sudoless-docker). Après un avertissement, cette opération vous ajoutera au groupe docker ; la commande docker et l’alias d fonctionneront alors de nouveau sans sudo.

N’oubliez pas d’essayer Lazydocker pour gérer vos conteneurs dans une TUI élégante avec Super + Shift + D ; il demande une autorisation lors de la première utilisation, sauf si vous avez activé Docker sans sudo.

Vous pouvez configurer dans Docker les bases de données couramment utilisées pour le développement local en choisissant Installer > Développement > Bases de données Docker dans le menu Omarchy.

CLI GitHub #

La CLI GitHub vous permet de vous authentifier avec votre compte GitHub et de l’utiliser pour cloner des dépôts privés. Elle est configurée comme l’une des commandes relais de Mise installées à la demande : la première fois que vous exécutez gh, elle s’installe automatiquement. Pour vous authentifier, exécutez gh auth login. Vous pourrez ensuite cloner des dépôts privés avec gh repo clone org/repo.

Cette commande vous permet également d’effectuer de nombreuses autres opérations sur GitHub. Exécutez simplement gh pour découvrir toutes les possibilités.

Une commande relais installée à la demande est également disponible pour ghui, afin de gérer vos pull requests dans une TUI. Et lazygit est préinstallé si vous souhaitez également piloter git lui-même depuis une TUI.
