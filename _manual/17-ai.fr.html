Omarchy accorde une place de premier plan aux agents IA de programmation, mais ne choisit pas de favori à votre place. À la place, chaque CLI majeure d’agent de programmation est préconfigurée sous forme de lanceur chargé à la demande. Ces lanceurs sont de minuscules scripts relais gérés par mise dans ~/.local/bin/, de sorte que rien n’est téléchargé avant la première exécution effective. Lancez n’importe lequel d’entre eux et authentifiez-vous lorsque vous y êtes invité :

Commande Agent
claude Claude Code
codex OpenAI Codex
opencode OpenCode
agy Google Antigravity CLI
copilot GitHub Copilot CLI
crush Crush
grok Grok CLI de xAI
pi Pi de Mario Zechner
omp Oh My Pi
ori Ori, l’environnement d’exécution d’OpenRouter

ori est un cas à part : il exécute les autres environnements d’agents avec l’ensemble du catalogue de modèles d’OpenRouter. Ainsi, ori claude, ori codex ou ori opencode démarrent ces agents avec le modèle que vous leur indiquez, tandis que ori code est le propre agent d’Ori.

Pour intégrer une CLI supplémentaire de la même façon, exécutez omarchy-mise-install <package> [command-name]. Les scripts relais sont mis à jour avec tout ce que gère mise lorsque vous exécutez omarchy update (ou l’alias mup).

L’agent par défaut #

Choisissez votre agent par défaut avec omarchy default agent <name> ou dans Configuration > Valeurs par défaut > Agent depuis le menu Omarchy (Super + Space). Si l’agent n’est pas encore installé, le sélectionner déclenche d’abord son installation. Sur une nouvelle installation, Omarchy vous invitera à faire ce choix au moyen d’une notification unique.

Une fois votre choix effectué, Super + Shift + Ctrl + A lance l’agent par défaut dans une fenêtre de terminal dédiée (ou affiche le sélecteur si vous n’avez pas encore choisi). Vous pouvez également le lancer directement sur une tâche avec omarchy agent prompt "Review this project". Les agents lancés de cette manière s’exécutent sans surveillance, dans leurs modes respectifs qui ne s’arrêtent pas pour demander confirmation : préparez-vous donc à les voir réellement agir ! Et comme les agents refusent de mémoriser que votre répertoire personnel est approuvé, les lancements depuis $HOME démarrent à la place dans ~/Work.

Il existe également des raccourcis dans le terminal : a exécute l’agent par défaut directement dans le terminal actuel, tandis que c, cx et cy démarrent respectivement OpenCode, Claude Code et Codex (là encore dans leurs modes d’approbation automatique). Les changements de thème sont également synchronisés avec les agents : Claude Code, Pi et OpenCode adoptent tous le nouveau thème lorsque vous changez celui d’Omarchy.

Le panneau des agents #

La barre supérieure affiche une icône d’agents dès qu’Omarchy détecte pour la première fois une activité de programmation assistée par IA sur la machine (et reste discrète jusque-là). Le panneau associé regroupe le suivi de tous les abonnements : votre forfait, le pourcentage consommé des quotas par session de 5 heures et par semaine (ou le solde prépayé restant), ainsi que l’utilisation des jetons par jour et par modèle. Claude Code, Codex et Fireworks sont pris en charge d’emblée.

Faites un clic gauche sur l’icône de la barre pour ouvrir le panneau, ou un clic droit pour lancer votre agent par défaut. Les données d’utilisation qui l’alimentent sont régénérées toutes les 15 minutes par omarchy agent usage-update, et le panneau peut même fusionner les données d’utilisation de vos autres machines par l’intermédiaire d’un dossier synchronisé. Consultez le README dans $OMARCHY_PATH/shell/plugins/agents/ pour connaître tous les paramètres.

Diagnostic des plantages #

Omarchy surveille systemd-coredump pour détecter les plantages de processus. Lorsqu’un programme subit une erreur de segmentation, vous recevez une notification « Processus planté » : cliquez dessus et le plantage est transmis à votre agent par défaut avec la compétence de diagnostic des plantages d’Omarchy, qui guide l’agent pour établir les faits à partir du vidage mémoire et déterminer si le plantage mérite d’être signalé au projet en amont. Vous pouvez également la lancer manuellement pour n’importe quel PID fourni par coredumpctl list avec omarchy agent crash <pid>.

La surveillance est activée par défaut. Désactivez-la dans Déclencheur > Activer/désactiver > Capture des plantages (ou avec omarchy toggle crash-capture) pour arrêter les notifications ; omarchy agent crash <pid> reste utilisable manuellement.

Les plantages peuvent également être masqués programme par programme, ce que le diagnostic vous propose à la fin. omarchy crash mute hyprland arrête les notifications pour ce seul programme, omarchy crash mute hyprland off les réactive et omarchy crash mute, utilisé seul, répertorie les programmes que vous avez masqués. La commande accepte aussi bien le chemin du binaire que son nom ; omarchy crash mute /usr/bin/hyprland produit donc le même résultat. Placez entre guillemets un nom contenant une espace, comme dans omarchy crash mute 'Some App'. Tous les autres programmes continuent de déclencher des notifications, et le programme masqué continue de planter : cela ne fait que masquer le rappel, sans rien réparer.

Applications de bureau #

Le menu Installer > IA propose également quelques applications graphiques d’IA : l’application de bureau ChatGPT et Grok Bot pour discuter avec les modèles de xAI.

LLM locaux #

Omarchy recommande deux solutions pour exécuter des LLM locaux : LM Studio et Ollama. LM Studio fournit une interface graphique permettant de rechercher des modèles à poids ouverts, de les installer et de les exécuter. C’est un excellent moyen de commencer facilement. Ollama propose une CLI offrant des fonctionnalités similaires. Toutefois, si vous découvrez les modèles locaux, je vous conseille de commencer par LM Studio. Vous pouvez installer l’un ou l’autre depuis Installer > IA dans le menu Omarchy.

La compétence Omarchy #

Les compétences d’agent aident l’IA à utiliser des outils précis d’une manière particulière, et Omarchy inclut une compétence par défaut pour personnaliser le système. Elle permet notamment de modifier votre configuration Hyprland, d’ajuster la barre ou même de créer entièrement un nouveau thème. Elle est ajoutée par lien symbolique aux répertoires de compétences de Claude Code (~/.claude/skills), Codex (~/.codex/skills), Pi (~/.pi/agent/skills), Antigravity (~/.gemini/config/skills) et à l’emplacement générique ~/.agents/skills, de sorte que la plupart des environnements d’agents la détectent automatiquement.

Vous devez toutefois considérer cette compétence comme expérimentale. Son efficacité varie selon les modèles. Il est préférable de commencer en mode plan afin d’avoir une idée des modifications que l’agent souhaite apporter. Préparez-vous ensuite à annuler les changements, voire à exécuter omarchy reinstall configs, si l’agent met tout sens dessus dessous.
