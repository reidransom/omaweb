Omarchy comprend un ensemble de fonctions shell qui simplifient les tâches courantes et encapsulent les appels de commandes aux paramètres complexes.

Compression #

  • compress [file/dir] : crée une archive tar.gz à partir du fichier ou du répertoire.
  • decompress [file.tar.gz] : extrait un fichier tar.gz.

Disques #

  • iso2sd [image.iso] : crée un support amorçable sur une carte SD à partir du fichier ISO indiqué, en permettant de choisir le disque de manière interactive.
  • format-drive [device] [name] : formate un disque entier avec une seule partition exFAT (qui fonctionne également sous Windows et macOS). Exécutez cette commande sans argument pour afficher les disques disponibles. Attention !

Dispositions de développement #

Des dispositions de développement instantanées à plusieurs volets pour tmux :

  • tdl [ai] : crée une disposition de développement Tmux avec votre éditeur, un agent d’IA et un terminal. Utilisez les alias d’agents, comme tdl c pour opencode ou tdl cx pour Claude Code, ou indiquez un second agent pour exécuter les deux, comme tdl c cx.
  • tds : crée un carré de développement Tmux avec un éditeur, le suivi des différences (via hunk diff --watch), un terminal et opencode.
  • tdlm [ai] : crée une fenêtre tdl pour chaque sous-répertoire du répertoire actuel.
  • tsl [count] [command] : crée un essaim de volets disposés en grille, exécutant tous la même commande (idéal pour les agents d’IA).

Les mêmes dispositions sont disponibles pour Herdr sous les noms hdl, hds, hdlm et hsl.

Arbres de travail Git #

  • ga [branch] : crée un nouvel arbre de travail et une nouvelle branche à côté du dépôt actuel, puis s’y place.
  • gd : supprime l’arbre de travail actuel et sa branche (après avoir demandé confirmation).

Surveillance avec rsync #

  • rsw [source] [destination] : lance en arrière-plan un processus de surveillance qui synchronise la source vers la destination avec rsync à chaque modification. La destination peut être un hôte distant, comme dans rsw ~/Work/app nyc-dev:Work/app.
  • lsw : répertorie tous les processus de surveillance actifs.
  • dsw : arrête tous les processus de surveillance actifs.

Redirection de ports SSH #

Idéal pour effectuer du développement web avec les privilèges de contexte sécurisé de localhost sur une machine distante.

  • fip : redirige un ou plusieurs ports d’un hôte distant vers localhost via SSH.
  • dip : déconnecte un ou plusieurs ports redirigés.
  • lip : répertorie toutes les redirections de ports SSH actives.

Supposons que vous lanciez un serveur de développement sur le port 3000 d’une machine accessible sous le nom nyc-dev. Vous pouvez alors exécuter fip nyc-dev 3000 pour rediriger ce port, de sorte que localhost:3000 accède en réalité à nyc-dev:3000, sans avoir besoin de certificats SSL pour établir le contexte sécurisé nécessaire au test des WebSockets ou de fonctionnalités similaires.

Reconnexion SSH #

ssh est lui-même enveloppé dans une fonction qui nettoie le terminal si une connexion est interrompue alors qu’un tmux, Herdr ou éditeur distant en a pris le contrôle, puis se reconnecte automatiquement lorsqu’une session interactive est interrompue (Ctrl-C arrête la boucle de nouvelle tentative).
