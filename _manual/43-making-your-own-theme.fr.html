Vous pouvez ajouter vos propres thèmes dans ~/.config/omarchy/themes. Il suffit de copier l’un des thèmes existants comme base (dans /usr/share/omarchy/themes), puis de le personnaliser à votre guise. Tant que votre thème se trouve dans ce dossier, il sera inclus dans le menu de sélection des thèmes.

Le principal fichier à modifier est colors.toml. Il définit la palette de couleurs qui sert ensuite à générer les configurations du terminal (Foot/Alacritty/Ghostty/Kitty), de btop, Chromium, Hyprland, Neovim, Helix, VSCode, Obsidian et de l’ensemble de l’interface d’Omarchy (barre supérieure, menu, notifications, OSD et écran de verrouillage).

Vous pouvez également utiliser l’application Aether incluse pour créer un nouveau thème à l’aide d’une agréable interface graphique permettant d’expérimenter avec les couleurs et de rechercher des arrière-plans. Il suffit de la lancer depuis le menu des applications avec Super + Alt + Space.

Ce que peut contenir un thème installé #

Un thème que vous créez vous-même dans ~/.config/omarchy/themes peut contenir tout ce que vous voulez — c’est votre machine et votre fichier, et Omarchy applique l’ensemble de son contenu.

Un thème que vous installez depuis le dépôt de quelqu’un d’autre avec omarchy theme install conserve tout ce qui concerne les couleurs, mais perd les quelques fichiers susceptibles d’exécuter du code sur votre machine : tout fichier .lua, les configurations de terminal (alacritty.toml, foot.ini, ghostty.conf, kitty.conf) et vscode.json. Le fichier hyprland.lua d’un thème contient du code Lua que votre compositeur exécute à la connexion, une configuration de terminal indique le programme lancé par votre terminal et vscode.json indique une extension VSCode à installer. Installer le thème de quelqu’un doit modifier l’apparence de votre bureau, jamais ce qu’il exécute.

Tout le reste fonctionne exactement comme l’auteur du thème l’a prévu : btop.theme, chromium.theme, helix.toml, icons.theme, shell.toml, les arrière-plans et les aperçus sont tous conservés. Seuls les éléments supprimés sont régénérés sur votre machine à partir de colors.toml.

Omarchy distingue les deux selon que le thème contient ou non son propre dépôt Git, que omarchy theme install laisse en place après le clonage. Ainsi, un thème que vous avez créé reste entièrement le vôtre, tandis qu’un thème récupéré sur Internet reste limité aux couleurs.

Mode clair #

Si vous créez un thème en mode clair, définissez mode = "light" en haut de votre fichier colors.toml. Il sera alors automatiquement associé au mode clair dans toutes les applications. (L’ancienne méthode consistant à placer un fichier vide nommé light.mode à la racine de votre thème fonctionne toujours elle aussi.)

Couleurs des icônes #

Si vous souhaitez assortir la couleur des icônes du gestionnaire de fichiers à votre thème, ajoutez un fichier nommé icons.theme contenant le nom du jeu d’icônes à utiliser. Par défaut, les options sont : Yaru Yaru-blue Yaru-dark Yaru-magenta Yaru-olive Yaru-prussiangreen Yaru-purple Yaru-red Yaru-sage Yaru-wartybrown Yaru-yellow.

Image de déverrouillage #

Les thèmes fournis avec des images unlock.png et preview-unlock.png seront répertoriés sous Style > Déverrouillage. Votre fichier unlock.png doit de préférence être un PNG transparent. Vous pouvez créer l’image d’aperçu avec omarchy plymouth preview.

Personnaliser le thème des applications non prises en charge par Omarchy #

Si vous utilisez une application qui ne figure pas dans cette liste, vous pouvez apprendre à Omarchy à lui appliquer un thème à l’aide d’un modèle. Placez dans ~/.config/omarchy/themed/ un fichier portant le nom de la configuration qu’il génère, suivi de l’extension .tpl, puis rédigez la configuration en utilisant {{ background }}, {{ foreground }}, {{ accent }}, {{ red }}, de {{ color0 }} à {{ color15 }}, ainsi que le reste de la palette comme variables de remplacement. Chaque fois que vous changez de thème, le fichier est régénéré avec les couleurs de ce thème.

Ce dossier contient un fichier alacritty.toml.tpl.sample entièrement commenté que vous pouvez prendre comme modèle — il répertorie toutes les variables disponibles, ainsi que les modificateurs _strip et _rgb pour les applications qui exigent des couleurs sans le # ou sous forme de valeurs RVB décimales. Vos modèles sont prioritaires sur ceux d’Omarchy, ce qui vous permet également de remplacer la façon dont un thème est appliqué à une application intégrée.

Distribuer votre thème #

Si vous souhaitez distribuer votre thème afin que d’autres puissent l’utiliser, vous devez le publier sur un serveur Git public, comme GitHub. Les utilisateurs pourront alors l’installer à partir de cette URL en choisissant Installer > Style > Thème dans le menu Omarchy. Il est recommandé de respecter la convention de nommage omarchy-[themename]-theme, car après l’installation, le thème apparaîtra correctement sous le simple nom [themename] dans le menu de sélection des thèmes.

La partie [themename] restante devient le nom du répertoire du thème. Elle doit donc pouvoir être manipulée sans risque par Omarchy : elle doit commencer par une lettre, un chiffre ou un tiret bas, et la suite peut contenir des lettres, des chiffres, ., _, + et -. Les majuscules sont automatiquement converties en minuscules, mais tout autre élément — une espace, un guillemet ou un caractère non anglais — entraîne le refus de l’installation au lieu d’être transformé en nom de répertoire. Ainsi, omarchy-tokyo-night-theme, omarchy-flexoki_light-theme et omarchy-c++-theme s’installent tous sans problème.

N’oubliez pas qu’une fois le thème installé depuis un dépôt, tous les fichiers .lua, les configurations de terminal et le fichier vscode.json qu’il contient sont supprimés. Ne concevez donc pas votre thème autour de ces fichiers.

Vous pouvez faire ajouter votre thème à la page des thèmes supplémentaires en envoyant une demande d’intégration au dépôt omarchy-site.
